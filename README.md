## 장을 가로지르는 공통 패턴

16개 사례의 동시성·멱등성 처리는 아래 여섯 가지 패턴의 조합입니다. 어떤 장이든 "어느 패턴을 어디에 썼는가"로 읽을 수 있습니다.

| 패턴 | 한 줄 원리 | 쓰인 곳 |
|---|---|---|
| **DB가 순서를 정한다** (유일 키 · 조건부 UPDATE · 행 잠금) | 조회는 참고 정보로 두고, 확정은 `INSERT ... ON CONFLICT`나 `UPDATE ... WHERE 상태 = 기대값`처럼 쓰기 자체가 판정이 되게 한다. 두 요청이 겹치면 먼저 커밋한 쪽만 성립하고 뒤쪽은 현재 상태를 보고 409를 받는다. 여러 행은 고정 순서로 잠가 교착을 없앤다 | 01 슬롯 유일 키 · 02 리비전 행 잠금 · 03 진도 행 잠금 · 05 주문 행 잠금 · 07 좌석 ID 순 조건부 UPDATE · 09 SKU 순 할당 차감 · 13 승인 claim · 14 릴리스 전이 · 16 알림 유일 키·임계치 조건부 갱신 |
| **상태 머신이 멱등성을 준다** | "현재 상태에서 허용된 전이만 적용"하면 같은 요청이 두 번 와도 두 번째는 무동작이다. 별도 멱등 키 없이 더블 클릭·재전송·콜백 중복이 처리된다 | 02 승인 더블 클릭 · 05 결제 콜백 중복·역전 · 07 좌석 상태 · 11 요청 종결 1회 · 13 승인·실행 · 14 릴리스 상태 · 15 번들 상태·평가 claim · 16 알림 ack 상태 전이 |
| **파티션 키로 줄을 세운다** | 같은 키의 사건을 한 소비자가 순서대로 처리하면 DB 잠금 경합이 소비자 앞의 대기열로 바뀌고, N건을 한 트랜잭션으로 묶어 처리량을 올린다. 배치 안 개별 실패(중복·검증 실패)는 롤백 사유가 아니라 "그 건의 결과 기록"이며, 롤백은 시스템 오류에만 쓴다 | 04 행사별 단일 확정자 · 06 캠페인별 소비자 · 08 문서별 소유 노드 · 10 사용자 키 처리기 · 12 문서 ID 파티션 · 16 차량 ID 파티션(상태·긴급 스트림) |
| **이중 쓰기는 체크포인트·Outbox로 하나로 만든다** | DB와 MQ, DB와 외부 시스템은 한 트랜잭션에 묶이지 않는다. 오프셋을 DB 체크포인트로 같은 트랜잭션에 저장하거나(소비 쪽), 메시지를 DB에 먼저 쓰고 발행기가 따로 전달한다(발행 쪽). 재전달은 멱등 키로 1회 결과가 된다 | 04 체크포인트 · 05·07·09 Transactional Outbox · 06 체크포인트 + ON CONFLICT · 11 사용량 (요청, 시도) 키 · 16 Edge 내구 버퍼 → at-least-once 발행 + (차량, 샘플 시각) upsert |
| **외부가 끼면 사가로 보상한다** | 결제·외부 채널처럼 DB 롤백으로 되돌릴 수 없는 단계가 있으면 로컬 트랜잭션 + 보상 단계로 나눈다. 쓰기 경계가 하나인 동안은 쓰지 않고(06), 경계가 둘 이상으로 갈라지는 순간 도입한다 | 05 승인·매입·환불 사가 · 07 결제 연동과 늦은 성공 환불 · 09 재할당(회수 중 → 확인 → 확정 → 증가) |
| **세대·버전으로 늦은 것을 거절한다** (Fencing · 버전 비교 · 포인터 전환) | 소유권·권한·릴리스에 단조 증가하는 번호를 두고, 번호가 작은 요청은 거절하거나 무시한다. 읽기 모델은 더 큰 버전만 적용하고, 전환은 포인터의 조건부 갱신 한 번으로 끝낸다 | 03 progress_epoch · 07 좌석 generation·투영 버전 · 08 노드 세대·권한 epoch · 10 보고 버전 포인터 · 11 시도 ID·버전 포인터 · 12 활성 버전 포인터 · 14 릴리스 포인터 · 15 번들 포인터·시도 ID·세트 버전 · 16 묶음 순번·설정 버전 |

**함께 따라오는 원칙**

- **조회는 느슨하게, 확정은 엄격하게**: 화면·캐시·읽기 모델은 낡을 수 있다고 전제하고, 정합성은 확정 지점 한 곳에서 보장한다(01 가능 화면, 07 읽기 모델, 12 검색 캐시).
- **멱등 키는 요청을 처음 만드는 쪽이 만든다**: 클라이언트가 UUID를 만들어 재시도에 재사용하고, 외부 호출 키는 주문·요청 ID에서 파생해 재시도마다 같게 한다(01·04·05·07).
- **접수 멱등은 최선 노력, 확정 멱등은 강제**: 앞단 중복 제거는 비용 절감용이고 최종 보장은 DB 유일 키가 맡는다(04·16 Edge 순번 창과 upsert).
- **과부하는 가장 앞단에서 끝낸다**: 뒤쪽이 참여자 수와 무관해지도록 Gateway에서 상한·시작 전·매진을 종결 응답으로 거절하고 재시도를 금지한다(04). 보내는 쪽이 정할 수 있으면 전송 시각 자체를 분산한다(16 차량 ID 위상).
- **결과 불명은 자동으로 되돌리지 않는다**: UNKNOWN 상태를 두고 조회로 수렴시키되, 되돌릴 수 없는 변경(결제·롤백·재시작)은 사람이 닫는다(05·07·13).
- **대사는 커서 시점으로 한다**: 쓰기가 계속되는 중에 원장과 잔액을 비교하려면 커서 이전만 합산해 같은 시점 스냅샷과 비교한다(06·08·10).
